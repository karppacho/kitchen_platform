# Макет интерфейса

Экспорт из Claude Design по техзаданию [FRONTEND.md](../FRONTEND.md).
**Это макет, а не исходники фронтенда.** Собрать его в приложение нельзя:
формат `.dc` — свой у дизайн-инструмента, со своим рантаймом. Отсюда берут
вёрстку и решения по виду, а не код.

## Файлы

| Файл | Что это |
|---|---|
| `Kitchen App.dc.html` | Сам макет: разметка + логика состояния |
| `support.js` | Рантайм `.dc`. Подключён относительной ссылкой — лежать должен рядом |
| `.thumbnail` | Превью в формате WebP. Служебный файл инструмента |

Имена оставлены ровно как выгрузил инструмент. Это осознанно: повторная
выгрузка после правок в дизайнере кладётся поверх без переименований, и
разница в git показывает изменения макета, а не возню с именами.

## Как открыть

Открыть `Kitchen App.dc.html` в браузере двойным щелчком. **Нужен интернет:**
React тянется с `unpkg.com`, шрифты IBM Plex — с `fonts.googleapis.com`.

Данные внутри — выдуманные, зашиты в файл. Обращений к нашему API нет ни
одного, поэтому бэкенд поднимать не надо.

## Что нарисовано

Четыре экрана целиком: справочник ингредиентов, блюда, карточка блюда,
сверка справочника. Плюс вход.

У каждого из четырёх два варианта — узкий и широкий, переключение на
1080 px. Требование «работает с телефона целиком» выполнено.

Остальные шесть разделов — заглушки с описанием: расчётка, конкуренты,
карточки ингредиентов, дегустации, чат с ассистентом.

## Известное расхождение

Тексты заглушек написаны по **старой** редакции ТЗ: там ещё говорится про
«правило „мобильная версия не нужна"» и разделы помечены `device: 'десктоп'`.
В самом ТЗ этого больше нет — минимальная ширина 360 px и работает всё.
Экранов это не касается, только пояснительных текстов у заглушек; чинить
стоит в дизайнере, а не здесь, иначе правку сотрёт следующая выгрузка.
