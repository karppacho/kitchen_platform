# Этап 6, первая часть: карточка — в справочник (спека)

Дата: 01.10.2026. Решения приняты с Александром в мозговом штурме 01.10.

## Контекст

Карточки ингредиентов (книга карточек, «Лист1») и справочник для расчёта себестоимости (книга кухни, лист ING) — две разные таблицы. После этапа 5 новые карточки заводятся на сайте и копятся на экране «Сверка справочника»: там видно, у каких карточек нет пары в справочнике. Сейчас «Сверка» только показывает. Довести карточку до справочника можно лишь руками в Google-таблице.

Этап 6 в общем плане — «редактирование справочника и блюд на сайте». Первой частью выбран **перенос карточки в справочник**: он сшивает карточки и калькулятор, а это главный разрыв проекта.

## Как устроен лист ING (проверено чтением 01.10.2026, процесс подтвердил Александр)

- Строки 2–28 — старые ингредиенты, все колонки вписаны руками.
- С 29-й строки (якорь — ячейка с формулой `=QUERY(...)` в колонке B, номер строки не зашивать) две формулы `QUERY` по листу-импорту книги карточек (`IMPORTRANGE`) сами выводят каждую карточку со статусом «Согласован: Да», в порядке строк книги карточек:
  - B категория, C название, D полное название — из колонок A, B, C карточки;
  - F изготовитель, G состав, H–K КБЖУ — из колонок E, G, H, I, J, K карточки.
- Ручные колонки, которые дописывает шеф или коммерция: A id, E «Короткое для айки», L «Цена за 1 кг (или 1 шт / 1 л)», M «Закупочная цена за упаковку», N «Единица измерения», O «Вес 1 шт, г», Q «потери перетарка/дефрост», R «потери нарезка», S «потери тепловая обработка», T «Статус».
- Формулы шефа:
  - P «Общие потери» = `SUM(Q+R+S)` — во всех строках;
  - L — в части строк формула от M (например `=M/6`, `=(1000*M)/2200`).
- Ниже последнего id лежат строки-заготовки: в L, M, N, Q, R, S, T — значения по умолчанию, P — формула, A и E пусты.
- Процесс сейчас: карточка становится «Да» → строка сама появляется в ING (с задержкой обновления `IMPORTRANGE`) → человек дописывает ручные колонки.
- **Хрупкость таблицы.** Ручные колонки ING стоят рядом с выводом `QUERY` по порядку строк. Если в середине книги карточек переключить «Да» или удалить строку, названия съедут относительно id и цен. Платформа добавляет карточки только в конец (этап 5), это безопасно. Ручные правки шефа могут сдвинуть строки.

## Решения

1. **Перенос = заполнение ручных ячеек той строки ING, которую `QUERY` уже создал для карточки**, а не добавление строки. Ячейки вывода `QUERY` (B–D, F–K) и формулы (P; L там, где она формула) платформа не пишет **никогда**. Запись в зону `QUERY` сломала бы вывод формулы у всего листа.
2. **Только согласованная карточка** (V = «Да») может быть перенесена: «Отбракован» в ING не попадает по устройству листа.
3. **Строка ищется двумя способами сразу.** По названию: строка зоны `QUERY` с C = название карточки и пустым A. По месту: якорь `QUERY` плюс номер карточки среди «Да» в свежем чтении книги карточек. Запись идёт, только если оба способа указывают на одну строку. Иначе — отказ с объяснением, без угадывания.
4. **id выдаёт платформа:** наибольший числовой id в ING плюс один, под очередью писателей. Человек видит id в форме, но не вводит.
5. **Поля формы:**
   - короткое имя для iiko;
   - единица: кг, л или шт;
   - цена за упаковку (M);
   - цена за единицу (L) — только если в этой строке L не формула, иначе поле скрыто с пометкой «считается в таблице»;
   - вес 1 шт — обязателен для «шт», для прочих пуст;
   - потери Q, R, S — по умолчанию 0, итог P показывается для сверки;
   - статус — «активный».

   Числа и проценты — `Decimal`, без `float`. Потери человек вводит в процентах («5» — это 5 %). В лист они пишутся долей (0,05): ячейки потерь в заготовке оформлены процентами, а импорт читает их как `Kind.PERCENT`. Оформление проверяется по свежему чтению. Если заготовка показывает значение не в процентах, запись отказывает с объяснением, а не угадывает.
6. **Права:** шеф, коммерция и разработчик (`require("chef", "commerce", "developer")`). Повар — нет.
7. **«Сверка» становится списком дел:**
   - неуверенная пара (`candidate` / `ambiguous`): «Это он» — выбрать кандидата, пара подтверждается только в базе (`link_confirmed_at`), таблица не меняется; «Это новый» — к форме переноса;
   - карточка без пары и «Да»: «Добавить в справочник»;
   - карточка без пары и не «Да»: пояснение без кнопки.
8. **После записи** — принудительный перенос книги кухни в базу. Новый ингредиент сразу появляется в «Справочнике», пара «карточка — ингредиент» подтверждается (`linked` и `link_confirmed_at`).
9. **ADR-0003, вторая ступень:** запись в книгу кухни открыта только листу ING и только ручным колонкам A, E, L, M, N, O, Q, R, S, T, только в строку с пустым A в зоне `QUERY`. Прочие листы и колонки книги кухни закрыты, как сейчас. Ворота записи становятся «книга → лист → колонки», а не «книга целиком».

## Путь записи

Механика писателя карточек (этап 5, `sync/writer.py`) применяется к заполнению строки:

1. Очередь писателей — та же advisory-блокировка (`SHEET_WRITE_LOCK_KEY`), с проверкой жизни замка перед записью.
2. Журнал `sheet_writes` с новым действием `fill`:
   - ключ запроса стабилен на карточку: `ing-fill:<id карточки>`;
   - открытая запись `verified` возвращается без записи («уже записано»);
   - `pending` разрешается перечитыванием.
3. Свежее чтение листа ING дважды — FORMATTED (значения) и FORMULA (где формулы) — и свежее чтение книги карточек (порядок «Да»).
4. Проверка шапки ING той же функцией, что у импорта (`check_header`). Расхождение — отказ, ноль записей.
5. Поиск строки (решение 3), затем проверки:
   - A пуст;
   - ни одна целевая ячейка не формула. L — пропускается, если формула;
   - в строке C совпадает с названием карточки.
6. Одна запись `values.batchUpdate`, RAW, только ручные ячейки этой строки. Пустые значения формы — `null` (ячейку не трогать), как у писателя карточек.
7. Перечитывание строки:
   - значения сверяются точно (UNFORMATTED);
   - раскладка — A пуст до записи, C = название, якорь `QUERY` на месте.

   Расхождение: если раскладка подтверждена — чистятся только свои ячейки, журнал `rolled_back`; иначе ничего не чистится, `failed` со снимком.
8. Успех: журнал `verified`, принудительный перенос книги кухни (`SyncCycle.run(force=True, books=("kitchen",))` с коротким ожиданием импортного замка, как после отправки карточки), подтверждение пары. Сбой переноса — успех с `imported=false`.

## Ответы человеку

| Ситуация | Ответ |
|---|---|
| Успех | «Записано в справочник: строка N, id X» |
| Карточка не «Да» | 409 «Карточка не согласована — в справочник попадают только «Да»» |
| Строки ещё нет в зоне `QUERY` (задержка `IMPORTRANGE`) | 409 «Строка ещё не появилась в справочнике — таблица подтягивает карточки с задержкой, попробуйте через несколько минут». Форма сохраняется на экране. |
| Название и место расходятся | 409 «Строки справочника сдвинуты относительно карточек — запись не сделана, проверьте лист ING» |
| В строке уже есть id | 200 «Ингредиент уже в справочнике — id N», пара подтверждается, записи нет |
| Несколько строк с тем же названием, место не помогает | 409 с объяснением, без угадывания |
| Обязательная ячейка — формула | 409 с объяснением |
| Шапка ING сдвинута | 503 «Колонки справочника изменились — сообщите разработчику» |
| Очередь занята дольше 30 с | 503 «Таблица занята — попробуйте ещё раз» |
| Сбой Google или неясный исход | 502 «Не удалось подтвердить запись — нажмите ещё раз: второй записи не будет» |
| Ошибка в поле формы | 422 с полем по-русски |

Изменяющие запросы — с `X-Kitchen-Csrf`, как всё API.

## API

- `GET /api/reconciliation` — как сейчас, плюс у строки:
  - `approved` (V = «Да»);
  - `actions` — какие действия доступны.
- `POST /api/reconciliation/{card_id}/confirm` `{ingredient_id}` — «Это он». Только база. Проверяется, что ингредиент — один из кандидатов этой карточки.
- `GET /api/reconciliation/{card_id}/reference-row` — предпросмотр для формы:
  - найдена ли строка (или почему нет);
  - следующий id;
  - какие ячейки формулы (L);
  - что уже подтянуто: название, категория, изготовитель, КБЖУ.

  Свежее чтение, без записи.
- `POST /api/reconciliation/{card_id}/to-reference` — тело формы → результат записи.

Числа — строками, как во всём API.

## Экран

«Сверка справочника» (`frontend/src/pages/Reconciliation.tsx`):
- действия у строк;
- форма — панелью на компьютере и снизу на телефоне, своей разметкой страницы. Компоненты таблиц `DataTable` и `PanelTablitsy` не трогаются: их переделывает чат мобильного вида.

Тексты — по-русски, простыми словами. Кнопки от 44 px, поля от 16 px.

## Вне этой части

- Правка существующих ячеек справочника, блюд и ТТК, журнал правок с разбором конфликтов, правка цены меню людьми — следующие части этапа 6, у каждой своя спека.
- Сигнал синхронизации «у id сменилось название» (сдвиг строк ING) — в ROADMAP.
- Перевод ING с выравнивания по порядку на связь по ключу — решение шефа, не платформы.

## Проверка

- Имитация листа ING, устроенная как настоящая:
  - якорь `QUERY`;
  - вывод `QUERY` в FORMATTED и пустота в FORMULA;
  - формулы P и L;
  - строки-заготовки;
  - одинаковые названия.

  Имитация книги карточек с порядком «Да».
- На каждую строку таблицы ответов — свой тест.
- Храповик: ячейки B–D, F–K и P листа ING не попадают ни в один запрос записи.
- Ворота: книга кухни открыта только для ING и ручных колонок; Блюда, ТТК, цена меню — закрыты.
- Миграция: действие `fill` в `sheet_writes`; вверх-вниз-вверх.
- Живая проверка с Александром: одна настоящая карточка «Да» → «Добавить в справочник» → строка ING заполнена в ручных колонках, формулы целы, ингредиент в «Справочнике», карточка ушла со «Сверки». `verify_golden.py` — 129 из 130.
