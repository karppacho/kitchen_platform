# «Сверка»: архивные тёзки и понятный выбор кандидата — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Откуда.** Живая проверка этапа 6 (02.10.2026). Подбор пар «карточка — ингредиент» исключает архивные позиции справочника ING (`domain/matching.py`, `ARCHIVED`): архивное не предлагается в новые блюда. Поэтому карточка, у которой в ING есть точный тёзка **в архиве**, выглядит «без пары» или «есть похожее», и экран предлагает «Добавить в справочник» или чужой активный ингредиент. На «Сверке» было 16 карточек, у 8 из них точный тёзка в архиве. Решение Александра 02.10 — **вариант 1:** точное совпадение названия с архивным ингредиентом платформа сама считает парой. Замечание Александра там же: кружок выбора кандидата непонятен.

**Goal:** «Сверка» показывает только настоящую работу; выбор кандидата — понятный; подсветка различий видит вставленные слова.

**Spec (решения Александра 02.10 — закон):**
1. Карточка, у которой среди **активных** ингредиентов нет точного тёзки, а среди **архивных** точный тёзка ровно один, — пара с ним, автоматически (`linked`, `link_confirmed_at` пуст — предложение, не решение человека; импорт может пересчитать). Карточка уходит со «Сверки». В новые блюда архивное по-прежнему не предлагается.
2. Активный точный тёзка важнее архивного; несколько активных тёзок — по-прежнему «неоднозначно».
3. Точных архивных тёзок несколько (активных нет) — «неоднозначно», кандидаты для «Это он» — эти архивные тёзки.
4. Пары, подтверждённые человеком (`link_confirmed_at`), не трогаются.
5. Кандидат один — без кружка: кнопка «Это он: «название»». Кандидатов несколько — каждый вариант выбирается нажатием на всю строку варианта, выбранный виден, затем «Это он». Двухшаговость при нескольких вариантах сохраняется (защита от промаха: подтверждённую пару экран не отменяет).
6. Подсветка различий (`NameDiff`) показывает и слова, которых нет в одном из названий: «Огурцы маринованные резанные» против карточки «Огурцы маринованные, не резанные» — видно, что в справочнике нет «не».

## Задача 1: пары с архивными тёзками (бэкенд)

**Файлы:** `backend/src/kitchen/domain/matching.py`, `backend/src/kitchen/sync/importer.py` (`_suggest_link`), `backend/src/kitchen/db/links.py` (`LinkReference.candidates`), тесты `backend/tests/unit/test_matching.py` (или ближайший), интеграционные тесты импорта пар и «Сверки».

**Устройство:** `NameIndex` хранит и архивных по названию; у `Match` — новое поле с точными архивными тёзками (заполняется, только когда активных точных нет), прежние свойства и их смысл не меняются. `_suggest_link`: активный точный один → `linked`; активных несколько → `ambiguous`; иначе архивный точный один → `linked` к нему; архивных несколько → `ambiguous`; иначе похожие → `candidate`; иначе `orphan`. `LinkReference.candidates` у `ambiguous`: активные тёзки, а если их нет — архивные тёзки.

**Тесты сначала:**
- домен: архивный точный тёзка виден в новом поле; при активном точном — поле пусто; `resolved`/`ambiguous`/`orphan`/`similar` для архивного случая — как раньше (архивное в подбор блюд не попадает);
- импорт: карточка с одним архивным точным тёзкой и похожим активным (случай «Корж для римской пиццы» / «Основа для римской пиццы») → `linked` к архивному, `link_confirmed_at` пуст; активный точный важнее архивного; два архивных тёзки → `ambiguous`, «Это он» предлагает их обоих и подтверждает выбранного; подтверждённая человеком пара не меняется;
- «Сверка» (`GET /api/reconciliation`): такая карточка в список не попадает.

**Мутации:** архивный важнее активного; архивные в `similar`; архивный тёзка у подбора блюд (`resolved` возвращает архивного).

**Коммит:** «Сверка: карточка с архивным тёзкой — пара сама, без «Добавить в справочник»».

## Задача 2: понятный выбор кандидата и подсветка вставок (фронтенд) + документы

**Файлы:** `frontend/src/pages/Reconciliation.tsx`, `frontend/src/ui/NameDiff.tsx`, новые стили в своём файле, тесты `frontend/tests/svarka.test.tsx` / соседние тесты «Сверки», `frontend/tests/nameDiff.test.tsx`; `docs/FRONTEND.md` (раздел о «Сверке»), `docs/ROADMAP.md` (снять долг «`NameDiff` не показывает вставку»; в описание этапа 6 — что архивные тёзки связываются сами).

**Тесты сначала:**
- один кандидат: кружка нет, кнопка «Это он: «название»» сразу подтверждает (тот же запрос, что сейчас), «Это новый» на месте;
- несколько кандидатов: нажатие на строку варианта выбирает его (видно выбранное; доступно с клавиатуры, программа чтения экрана понимает выбор), «Это он» недоступна до выбора;
- `NameDiff`: вставка и удаление слов в обе стороны («Огурцы маринованные, не резанные» / «Огурцы маринованные резанные» — «не» показано как отсутствующее в справочнике), прежние случаи — как были;
- кнопки от 44 px, тексты по-русски.

**Мутация:** при одном кандидате кнопка без названия кандидата; вставка не показана.

**Коммит:** «Сверка: выбор кандидата без кружка, подсветка пропущенных слов»; документы — отдельным коммитом.
