# Карточка — в справочник: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** «Сверка справочника» превращается в список дел. «Это он» подтверждает пару только в базе. «Добавить в справочник» заполняет ручные ячейки строки ING, которую формула `QUERY` уже создала для согласованной карточки, — безопасной записью, с журналом и мгновенным переносом в базу.

**Architecture:** Используется путь записи этапа 5 (очередь писателей в базе, журнал `sheet_writes`, сверка после записи). К нему добавляются:
- ворота записи «книга → лист → колонки»;
- чистый доменный модуль поиска строки и разбора формы;
- писатель заполнения строки;
- три ручки `/api/reconciliation/*`;
- действия и форма на экране «Сверка».

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, gspread 6.2 (`values_batch_get` с FORMATTED/FORMULA), React 18, TanStack Query 5, vitest + msw.

**Spec:** `docs/superpowers/specs/2026-10-01-spravochnik-iz-kartochki-design.md` — закон. Где план и спека расходятся, права спека.

## Global Constraints

- В листе ING пишутся **только** ручные ячейки A, E, L (если в этой строке не формула), M, N, O, Q, R, S, T. Пишутся только в строку зоны `QUERY` с пустым A. Ячейки вывода `QUERY` (B–D, F–K) и формулы (P, L-формула) — **никогда**. Прочие листы и колонки книги кухни остаются закрытыми.
- Строка находится по названию и по месту одновременно; при расхождении — отказ без записи. id = максимальный числовой id ING + 1 под очередью писателей.
- Одна запись `values.batchUpdate` RAW; пустое — `null`; после — перечитать и сверить; откат — только своих ячеек и только при подтверждённой раскладке; журнал `sheet_writes` с действием `fill`; ключ запроса `ing-fill:<id карточки>`.
- Деньги, КБЖУ, проценты — `Decimal`, никаких `float`/`Number()`/`parseFloat`. Потери вводятся в процентах, пишутся долей; оформление ячейки сверяется по свежему чтению.
- Права: `chef`, `commerce`, `developer`. Изменяющие запросы — с `X-Kitchen-Csrf`.
- Слои import-linter: `kitchen.web | kitchen.worker` → `kitchen.cards` → `kitchen.sync | kitchen.llm` → `kitchen.db` → `kitchen.domain`. mypy strict для `domain`, `sync`, `llm`, `cards`.
- Не трогать `frontend/src/ui/DataTable.tsx`, `ui/PanelTablitsy.tsx`, `shell/Layout.tsx`, `shell.css`, `pages/DishDetail.tsx` — их переделывает чат мобильного вида.
- В репозитории нет названий сети и юрлица клиента (в том числе в названии листа-импорта карточек), имён людей, почт, id таблиц и папок.
- Миграции — только обратимые, по чек-листу migration-guard. Правки `CLAUDE.md` и `.claude/agents/*` — только с согласия Александра.
- Коммиты по-русски с `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Windows: файлы — только Write/Edit, после правок `git ls-files --eol` → `w/lf`; перед `uv` — `VIRTUAL_ENV=`.

## Задача 1: ворота записи «книга → лист → колонки», ADR-0003 вторая ступень

**Файлы:** `sync/ownership.py`, `sync/specs.py` (если нужна пометка формульных колонок), `tests/unit/test_ownership.py`, `docs/adr/0003-platforma-pishet-v-tablitsu.md` (раздел «Вторая ступень»: только ING, только ручные колонки, только строка с пустым A в зоне `QUERY`; почему зона `QUERY` неприкасаема; хрупкость выравнивания по порядку).

**Тесты сначала:**
- `INGREDIENTS.writable()` = ровно A, E, L, M, N, O, Q, R, S, T;
- B, C, D, F–K, P → отказ «заполняет формула таблицы»;
- `DISHES`, `TTK`, `PACKAGING`, `COOKING_METHODS`, расчётки — `writable()` пуст;
- `INGREDIENT_CARDS` — как сейчас (A–P, S–V);
- `BOTS_ALIVE=True` закрывает всё;
- храповик: из всех описаний листов `writable()` непуст только у `INGREDIENT_CARDS` и `INGREDIENTS`;
- прежние тесты владения переписаны, не удалены.

**Мутации:** открыть книгу кухни целиком; добавить P в ручные; забыть проверку листа.

**Коммит** «Запись открыта листу ING: только ручные колонки (ADR-0003, вторая ступень)».

## Задача 2: домен — форма справочника и поиск строки

**Файлы:** `domain/reference_row.py`, `tests/unit/test_reference_row.py`.

**Тесты сначала:**
- **Форма:**
  - «12,5» → `Decimal("12.5")`;
  - «abc» → ошибка у поля;
  - единица только кг/л/шт;
  - для «шт» вес обязателен и > 0, для прочих — пуст;
  - потери «5» → `Decimal("0.05")`, по умолчанию 0, каждая 0–100;
  - короткое имя — обязательно, обрезка пробелов, предел длины;
  - статус — «активный».
- **`next_reference_id`:** `["1", "130", "99", "", "x"]` → «131»; пусто → «1».
- **`find_query_anchor`:** находит строку с `=QUERY(` в колонке B; нет якоря → ошибка «формула подтягивания карточек не найдена».
- **`locate_row`:**
  - по названию и месту одна строка → `Located`;
  - строки нет (задержка `IMPORTRANGE`) → `NotFound.NOT_YET`;
  - название и место расходятся → `NotFound.SHIFTED`;
  - в строке уже есть A → `AlreadyFilled(id)`;
  - два одинаковых названия, место выбирает одну → `Located`;
  - место не помогает → `NotFound.AMBIGUOUS`;
  - карточка не «Да» → `NotFound.NOT_APPROVED`.
- **`formula_cells`:** L формула → в списке; P всегда.

**Мутации:** id по текстовой сортировке; поиск только по названию; потери без деления на 100.

**Коммит** «Домен справочника: форма и поиск строки ING по названию и месту».

## Задача 3: писатель заполнения строки, журнал `fill`

**Файлы:**
- `sync/reference_writer.py`;
- общие куски с `sync/writer.py` — вынести без изменения поведения писателя карточек; все его тесты зелёные без правок;
- `db/models.py` (`SheetWrite.action`) и миграция `…_sheet_writes_fill.py` (CHECK `action in ('append','fill')`, обратимая);
- `tests/conftest.py` — фальшивая книга кухни с листом ING как настоящий: якорь `QUERY` в B и F, вывод `QUERY` виден в FORMATTED и пуст в FORMULA, P = формула, L-формула в части строк, строки-заготовки с умолчаниями в процентном оформлении, одинаковые названия; фальшивая книга карточек с порядком «Да»;
- `tests/unit/test_reference_writer.py`, `tests/integration/test_reference_writer.py`.

**Порядок `fill`** (спека, раздел «Путь записи»): ворота → очередь писателей → журнал по `request_key` (`verified` → вернуть; `pending` → перечитать) → чтение ING FORMATTED + FORMULA и книги карточек → `check_header` → `locate_row` и проверки ячеек → id = max + 1 → журнал `pending` со снимком строки → одна `values_batch_update` RAW (только ручные ячейки, L пропускается, если формула) → перечитать и сверить → `verified` / `rolled_back` / `failed`.

**Тесты сначала:**
- тело записи содержит только A, E, L/M, N, O, Q, R, S, T этой строки; B–D, F–K, P — никогда (храповик по телу запроса);
- L-формула не пишется;
- потери долей;
- `null` для пустого;
- задержка (строки нет) → ноль записей, текст из спеки;
- сдвиг → ноль записей;
- A уже заполнен → `already`, ноль записей;
- повтор `request_key` → ноль запросов;
- подмена ячейки после записи → чистятся только свои;
- шапка сдвинута → ноль записей;
- два одновременных переноса разных карточек → разные строки и id подряд;
- миграция вверх-вниз-вверх.

**Мутации:** писать всю строку A–T; без проверки формулы L; без сверки места.

**Коммит** «Писатель строки справочника: заполнение ручных ячеек ING, журнал fill».

## Риски

- **`IMPORTRANGE` подтягивает с задержкой.** Честный 409 «ещё не появилась», ввод формы сохраняется.
- **Шеф сдвигает строки книги карточек.** Поиск по названию и месту ловит сдвиг, запись не делается.
- **Чужая правка той же строки в ту же секунду.** Перечитывание и откат только своих ячеек, как в этапе 5.
- **Процентное оформление ячеек потерь иное, чем ожидается.** Отказ с объяснением, а не угадывание.
