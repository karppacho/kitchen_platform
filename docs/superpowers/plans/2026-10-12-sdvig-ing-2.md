# Сдвиг строк ING, часть 2: пропавшее название и ручной обход — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Откуда.** Часть 1 (PR №38, слит 12.10, `main` 2fbd1d1) останавливает перенос книги кухни, когда в листе ING у 2 и больше id название пришло от другого id. Итоговое ревью нашло два предела: (1) уход последней или предпоследней согласованной карточки даёт одно чужое название или пустое — ниже порога, сдвиг проходит молча; (2) если в базе уже лежат сдвинутые названия (восстановление из дампа 04–11.10, круговая перестановка), признак держит перенос даже при верном листе, и обхода нет. Решения Александра 12.10: «пропало название» — считать сигналом; обход — сделать, как правильнее и безопаснее.

**Spec (решения Александра 12.10 — закон):**
1. **Пропавшее название.** Строка листа ING с непустым id и пустым названием (после `normalise_name`), а у этого id в базе название было (непустое), — «id потерял название». Считается каждая такая строка, даже если в другой строке листа у того же id название есть: импорт берёт последнюю строку id, и пустая копия стёрла бы название (так бывает, если после выравнивания не очистить ручные ячейки последней строки). Сигнал — **1 такой id и больше** (законно такой строки не бывает). Признак сдвига теперь: id с чужим названием ≥ 2 **или** id, потерявших название, ≥ 1 (счёт — по уникальным id).
2. **Текст причины** — тот же `SHIFT_PROBLEM_START`, дальше: сколько id получили чужое название и/или сколько потеряли его, примеры в порядке строк (до трёх, «и ещё N»), пропавшее — «стр. N, id M: было «X», стало пусто»; совет: «так бывает, когда в книге карточек удалили согласованную карточку или сменили ей статус: верните ручные колонки (A, E, L–O, Q–T) к своим названиям, а в строках без названия очистите их — перенос возобновится сам». В `details` — все строки, пропавшее — «стр. N, id M: «X» → пусто».
3. **Ручной обход — только у разработчика и только точным числом.** `scripts/import_sheets.py --accept-shift N`: если признак сработал и **число разных id в нём (чужое название ∪ пропавшее) ровно N** — книга кухни переносится, несмотря на признак; в журнал прогонов — отдельная запись «сдвиг строк ING принят вручную: N id — …» (с подробностями, как у сбоев); на экран — полный список. Число не совпало (лист изменился, пока смотрели) — отказ, как без флага, и в выводе — сколько найдено сейчас. Признака нет — флаг ни на что не влияет. Воркер, «Сверка» и короткий перенос после записи флага не получают никогда. Флаг не обходит ни сдвиг колонок, ни непрочитанный лист — только этот признак.
4. **Документы:** ROADMAP — долг «Лист выровнен, а причина держится — база старше листа» закрыт обходом (порядок: сверить список в выводе с листом, убедиться, что лист верен, запустить с `--accept-shift N`); в правиле выравнивания и в ADR-0003 граница «уход последней/предпоследней карточки не ловится» заменяется на новую; FRONTEND.md — пример причины с пропавшим названием, если причины там перечислены; журнал CLAUDE.md — в записи 04–12.10 «при «название ушло к другому id»» → «при «название ушло к другому id или пропало»».
5. API и фронтенд не меняются.

## Задача 1: пропавшее название и текст причины

**Файлы:** `backend/src/kitchen/domain/ing_shift.py` (`LostName`, `lost_names`, признак с двумя частями), `backend/src/kitchen/sync/cycle.py` (`shift_problem`, `shift_details`, проверка в `run`), тесты `backend/tests/unit/test_ing_shift.py`, `backend/tests/unit/test_cycle.py`, `backend/tests/integration/test_cycle.py`; докстринги модулей.

**Тесты сначала:** id с пустым названием, в базе было → 1 потерянный, сдвиг; в базе название пустое → не в счёт; id новый (нет в базе) с пустым названием → не в счёт; id в двух строках, одна с названием, другая пустая → потерянный (строка пустой); уход последней карточки (у последнего id пусто, чужих 0) → сдвиг; уход предпоследней (1 чужое + 1 пустое) → сдвиг; только чужие названия — как в части 1 (порог 2); текст причины: только чужие, только пропавшие, оба вида, «и ещё N» общий по строкам; `details` с «→ пусто». Интеграция: последняя карточка ушла → кухня не переносится, названия в базе прежние; выровняли → переносится.

**Мутации:** пропавшее при пустом названии в базе; пропавшее не засчитано, если у id есть другая строка с названием; порог пропавших 2 вместо 1; пропавшие не в числе id причины.

**Коммит:** «Сдвиг ING: пропавшее название — тоже сигнал».

## Задача 2: ручной обход `--accept-shift N` и документы

**Файлы:** `backend/src/kitchen/sync/cycle.py` (`SyncCycle.run(..., accept_shift: int | None = None)`: при признаке и совпадении числа — перенос и запись журнала «принят вручную»; несовпадение — отказ с причиной и пояснением в `details`), `backend/scripts/import_sheets.py` (`argparse`, `--accept-shift N`, вывод), тесты `backend/tests/integration/test_cycle.py`, `backend/tests/unit/test_import_sheets.py`; документы по Spec 4.

**Тесты сначала:** сдвиг + `accept_shift` равен числу → `imported`, названия из листа в базе, причина снята, в журнале запись «принят вручную»; не равен → `failed`, причина та же, в `details` — найдено сейчас M; признака нет + флаг → обычный перенос, лишней записи журнала нет; сдвиг колонок + флаг → отказ, как без флага; воркер (`run()` без параметра) при сдвиге — отказ, как раньше; скрипт разбирает `--accept-shift 74`, отвергает отрицательное и не число, без флага — прежнее поведение, код выхода прежний.

**Мутации:** принимать при любом числе; принимать без флага; флаг обходит сдвиг колонок; запись журнала не делается.

**Коммит:** «Сдвиг ING: ручной обход точным числом в import_sheets.py, документы».
