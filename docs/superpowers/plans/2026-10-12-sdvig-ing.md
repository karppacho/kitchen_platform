# Сдвиг строк ING: книга кухни не переносится — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Откуда.** 04.10.2026 в книге карточек у одной согласованной карточки сменили статус на «Нет», а две карточки-дубля удалили. Правили руками в Google-таблице. Формула `QUERY` в листе ING выводит согласованные карточки подряд (B–D, F–K), а ручные колонки (A — id, E, L–O, Q–T) стоят рядом и с выводом связаны только номером строки. Из вывода ушли три строки, и всё ниже съехало ступенькой на 1, 2 и 3 строки: у 77 id название и КБЖУ стали чужими. Воркер молча перенёс это в базу и переименовал ингредиенты по id. Сайт 8 дней (до 12.10) показывал в составах блюд чужие названия и КБЖУ. Себестоимость не пострадала, потому что она привязана к id и ручным ценам. Заметили 12.10 при перепривязке эталона «штучных»: из 130 блюд разошлись 114. 12.10 лист выровняли руками; по дампу базы от 03.10 расхождений нет. Платформа сама эти правки не делала — это видно по журналу `sheet_writes`, истории версий книги и журналу nginx. Но поймать сдвиг ей было нечем: это долг ROADMAP «Сигнал «у id сменилось название»».

**Spec (решения Александра 12.10 — закон):**
1. **Признак сдвига.** id «получил чужое название», если в листе у него название X (после `normalise_name` из `kitchen.domain.matching`), в базе у него было другое, а X в базе носил другой id, который в листе это название потерял (у него теперь иное или его нет в листе). Пустое название, новый id, id, ушедший из листа, — не в счёт. Сдвиг — **2 и больше** таких id в одном чтении: при сдвиге их десятки, а одиночное переименование шефа (в том числе в имя, которое у соседа осталось) — 0.
2. **Сдвиг — книга кухни не переносится**, как при сдвинутых колонках: старые данные остаются, причина уходит в `sync_state` и на сайт (полоса свежести), в журнал прогонов — один раз на смену причины. Карточки переносятся как обычно. Проверка — в цикле синхронизации, при переносе кухни, и при `force` (ручной `scripts/import_sheets.py`) тоже. Причина снимается сама, когда лист выровняли.
3. **Текст причины** (для шефа, на сайт) — начинается словами `в листе «ING» строки съехали относительно id:`; дальше — сколько id получили чужое название и до трёх примеров «стр. 116, id 115: было «Сырная котлета», стало «Фритюрное масло»», и что делать: «так бывает, когда в книге карточек удалили согласованную карточку или сменили ей статус; верните ручные колонки (A, E, L–O, Q–T) к своим названиям — перенос возобновится сам». Полный список (все id, у кого было название) — в `details`: в журнал и лог, не на сайт.
4. **«Сверка»: пока у книги кухни причина «строки съехали», «Добавить в справочник» и предпросмотр его формы отказывают** (503) текстом «Перенос в справочник отложен: в листе ING строки съехали относительно id, и таблица кухни не переносится на сайт. Сначала выровняйте лист ING». «Это он» (только база) — как прежде.
5. **Свободная строка книги карточек**: справа от карточки (колонки после V) ячейка с галочкой без отметки («FALSE» или «ЛОЖЬ») строку не занимает; отмеченная галочка и любой текст правее V — занимают, как прежде (заметка шефа). В A–V — как прежде. Причина: 06.10 шеф добавил колонку галочек W до строки 333, и карточка «Сырники» легла в строку 334.
6. **Пары карточек** (неподтверждённая пара пересчитывается по названию и при сдвиге уезжает за ним) — не в этой правке: с пунктом 2 сдвинутые названия до базы не доходят. Записать в долги ROADMAP.
7. API не меняется; фронтенд не меняется — экран показывает `problem` и текст отказа как есть.

## Задача 1: признак сдвига и отказ переноса кухни

**Файлы:** новый `backend/src/kitchen/domain/ing_shift.py`; `backend/src/kitchen/sync/cycle.py` (проверка в `SyncCycle.run`, тексты причины, константа начала причины, докстринг модуля); тесты `backend/tests/unit/test_ing_shift.py` (новый), `backend/tests/integration/test_cycle.py`.

**Интерфейс (domain):**
```python
@dataclass(frozen=True, slots=True)
class SheetName:
    ref_id: str   # id из колонки A, как читает импорт (_text)
    name: str     # название из колонки C, как в листе
    row: int      # номер строки листа, с единицы

@dataclass(frozen=True, slots=True)
class MovedName:
    ref_id: str
    row: int
    was: str      # название этого id в базе
    now: str      # название из листа
    owner: str    # id, у которого это название было в базе (наименьший при нескольких)

SHIFT_MIN_MOVED = 2

def moved_names(known: Mapping[str, str], sheet: Sequence[SheetName]) -> tuple[MovedName, ...]  # в порядке строк листа
def looks_shifted(moved: Sequence[MovedName]) -> bool  # len >= SHIFT_MIN_MOVED
```
`known` — id → название у ингредиентов в базе без `removed_at`. Сравнение названий — через `normalise_name`; в `MovedName` — названия как есть.

**Цикл:** для книги `kitchen`, которая идёт в перенос (изменилась или `force`), — после решения по отпечатку и до точки сохранения: прочитать `known` в той же сессии (после очереди импорта), собрать `SheetName` из прочитанного листа ING (строки с непустым id — как `_identified` импорта), `moved_names`; при `looks_shifted` — `_record_failure` (причина по Spec 3, `details` — весь список), исход `failed`, книга не переносится. Константа `SHIFT_PROBLEM_START = "в листе «ING» строки съехали относительно id"` — открыта для «Сверки» (задача 2).

**Тесты сначала (unit, domain):** без изменений → пусто; одиночное переименование → пусто; переименование в имя, которое сосед сохранил (дубль) → пусто; сдвиг блока на 1 (как в живом листе: удалили строку `QUERY` в середине) → все id ниже места разрыва, `owner` — соседний id; обмен двух названий → 2 (сдвиг); новый id в листе → пусто; id ушёл из листа → пусто; пустое название → пусто; разница только в регистре, «ё», пунктуации → пусто; дубль в базе («Сахар» у id 2 и 3) съехал к id 4 → id 4 в списке, `owner` — тот, кто имя потерял; `looks_shifted` — 1 → нет, 2 → да.

**Тесты сначала (integration, cycle):** первый перенос, затем лист ING со сдвигом (у трёх id названия соседей) → `kitchen` `failed`, причина начинается с `SHIFT_PROBLEM_START`, в ней число и пример со строкой и id, названия в базе прежние, карточки перенесены; тот же сдвиг вторым циклом — одно событие журнала; `force=True` — тоже отказ; лист выровняли → перенос, причина снята; одиночное переименование → перенос как обычно; первый перенос в пустую базу со «сдвигом» → перенос (сравнивать не с чем).

**Мутации:** порог 1 вместо 2; сравнение без `normalise_name`; не проверять, что владелец имя потерял; проверка только без `force`; причина без примеров.

**Коммит:** «Синхронизация: сдвиг строк ING — книга кухни не переносится, причина на сайте».

## Задача 2: «Сверка» при сдвиге и свободная строка книги карточек

**Файлы:** `backend/src/kitchen/cards/reference.py` (отказ `preview` и `to_reference` по Spec 4 — до чтения листа; докстринг модуля: абзац «Защита действует, только пока база помнит…» — теперь база помнит, пока лист не выровняли); `backend/src/kitchen/sync/writer.py` (`find_free_row` по Spec 5, докстринги про «пустую во всю ширину»); `docs/adr/0003-platforma-pishet-v-tablitsu.md` (п. 3 — галочки правее V); тесты `backend/tests/integration/test_reconciliation_api.py` (или `test_reference_flow.py` — где ближе), `backend/tests/unit/test_writer.py`.

**Тесты сначала:** причина книги кухни начинается с `SHIFT_PROBLEM_START` → предпросмотр и «Добавить в справочник» — 503 с текстом Spec 4, писатель не вызывался, журнал `sheet_writes` пуст; другая причина у кухни (например, «лист «ТТК» не прочитан») → перенос как прежде; «Это он» при сдвиге — работает. `find_free_row`: «FALSE» и «ЛОЖЬ» правее V не занимают строку (живой случай: карточки до 117, галочки W до 333 → 118); «TRUE» правее V — занимает; текст правее V — занимает (как раньше); «FALSE» в A–V — занимает.

**Мутации:** отказ только у `to_reference` (без предпросмотра); любая причина кухни блокирует перенос; «FALSE» не пустое правее V; «FALSE» пустое и внутри A–V.

**Коммит:** «Сверка: перенос в справочник отложен при сдвиге ING; свободная строка карточек — галочки справа не мешают».
