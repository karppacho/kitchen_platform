# Kitchen Platform — записка для агента

Общаемся на русском и только на русском.

Веб-платформа R&D кухни сети «Тим Кук» (ООО «Гастрономия»). Заменяет три
Telegram-бота: `kitchen_bot` (себестоимость, ТТК, расчётка, конкуренты),
`pizza_bot_new` (карточки ингредиентов), `tasting_bot` (слепые дегустации).

**Этот файл лежит в git.** В `kitchen_bot` аналогичная записка на 82 КБ была
в `.gitignore`: на GitHub её нет, и потеря машины уносит её целиком. Здесь
так не делаем.

## Главные правила, которые НЕЛЬЗЯ нарушать

1. **Пока живы Telegram-боты, платформа не пишет в общие Google-листы.**
   Боты продолжают туда писать; два писателя без координации — гонка, в
   которой проигрывает шеф. Синхронизация на этом этапе только в одну
   сторону: лист → БД.

2. **Google-таблица остаётся рабочей площадкой шефа.** Её структуру не
   меняем без согласования. Часть колонок принадлежит людям (цена меню,
   цены коммерсов, статусы, комментарии) — их мы не перезаписываем никогда.

3. **Все числа считает код, не LLM.** Модель получает результат функции и
   пересказывает его. Никакой арифметики в промптах.

4. **Только polza.ai.** Прямой доступ к OpenAI и Anthropic из РФ закрыт;
   предложение «пойти напрямую» сломает прод.

5. **Деньги и веса — `Decimal`.** Ни одного `float` в расчётном пути.

6. **Слои разделены, и это проверяет CI.** `kitchen.domain` не импортирует
   ни транспорт, ни хранилище, ни SDK внешних сервисов. Контракт описан в
   `[tool.importlinter]`, нарушение роняет сборку.

Инварианты предметной области (потери, штучные, архив, тёзки) вынесены в
агента `domain-guard` — см. `.claude/agents/`. Он и есть их источник истины.

## Архитектура

```
backend/src/kitchen/
├── domain/    чистая логика: расчёты, правила, парсеры. Ничего не импортирует
├── db/        SQLAlchemy: модели и репозитории
├── sync/      обмен с Google Sheets, правила владения колонками
├── web/       FastAPI: ручки, аутентификация
└── worker/    фоновые задачи, кроны, скрапинг
```

Направление зависимостей строго вниз: `web`/`worker` → `sync` → `db` → `domain`.

## Проверки

`make check` — всё, что блокирует PR: ruff, mypy, import-linter, офлайн-тесты
бэкенда; типы, eslint и тесты фронтенда. Сборку фронтенда и образ nginx
проверяет CI.
Требование к блокирующему CI: **укладываться в пять минут**. Медленное
(e2e, LLM-евалы) живёт отдельно и в PR не входит.

Слияние в `main` — только через PR с зелёным CI. С 23.09.2026 это держит
защита ветки: прямой push в `main` отклоняется, а PR сливается, только когда
все 8 проверок CI зелёные и ветка свежая относительно `main`.

## Как проверять, что работа сделана

| Заявление | Чем доказывается |
|---|---|
| «тесты проходят» | вывод `make test` с числом пройденных |
| «типы в порядке» | вывод `make types` |
| «слои не нарушены» | вывод `make arch` |
| «расчёт не изменился» | золотой файл `tests/golden/` не сдвинулся |
| «работает на сервере» | `/healthz` отдаёт ожидаемый хеш коммита |

«Прошлый прогон», «должно пройти» и «я не менял это место» доказательствами
не являются. Не объявляй тесты зелёными, если они красные.

## Что НЕ делать

- Не подгонять код под золотой файл. Эталон перепривязывают осознанно и с
  объяснением, почему новое число правильнее старого.
- Не добавлять запись в общие листы, пока боты живы (правило 1).
- Не выносить `service_role`-ключ Supabase за пределы бэкенда — он обходит
  все проверки прав.
- Не публиковать наружу ничего, кроме 80 и 443. Особенно Supabase Studio:
  за ним полный доступ к базе, а защита — одна пара логин/пароль. Привязка
  портов делается только в оверлее и только с тегом `!override`: списки
  портов при слиянии дописываются, а не заменяются.
- Не чинить симптом, не поняв причину. Три неудачные попытки подряд — стоп,
  разбираемся заново.

## Журнал разборов

Сюда пишем инциденты и их причины — так же, как это делалось в `kitchen_bot`.
Унаследованные разборы, объясняющие текущие решения:

- **04.08.2026** (`kitchen_bot`) в «Блюда» тянулись сорок строк с одним
  статусом, и `append_row` отправлял новую запись вниз таблицы. Отсюда
  правило: свободная строка ищется по ключевой колонке.
- **04.08.2026** создалось блюдо с UC 1398 ₽ при цене меню 280 ₽, и система
  промолчала. Отсюда: себестоимость выше цены — всегда предупреждение.
- **17.08.2026** многострочная команда с Windows приехала на сервер с CRLF,
  bash порвал кавычки и запустил лишний процесс на бою. Отсюда: деплой — это
  скрипт в репозитории, вызываемый одним словом.
- **19.08.2026** после `git pull` забыли `systemctl restart`, процесс работал
  со старым кодом. Отсюда: перезапуск — обязательный шаг `deploy.sh`.
- **08.09.2026** Telegram закрыл последний доступный IP, и три бота встали.
  Молча: aiogram бесконечно ретраится, `systemctl status` показывает
  `active (running)`. Сломанное состояние видно только по журналу.
- **10.09.2026** второй прогон импорта упал с `DuplicatePreparedStatement:
  prepared statement "_pg3_0" already exists`. psycopg3 сам готовит
  повторяющиеся запросы, а в transaction-режиме пулера соединение под
  нами меняется. Отказ отложенный: первый импорт в пустую базу прошёл
  целиком, потому что вставки обходились без подготовки, а обновления
  во втором — нет. Лечится `prepare_threshold=None` в connect_args.
  Отсюда правило: любую работу с базой через пулер проверять **дважды
  подряд**, а не один раз.
- **09.09.2026** при установке Supabase оверлей игнорировался, потому что в
  `.env` задан `COMPOSE_FILE` с одним именем файла. `docker compose config`
  при этом отрабатывал без ошибок, показывая конфигурацию без наших правок.
  Отсюда: проверять не «команда прошла», а «в выводе есть то, что я менял».
- **10.09.2026** ТЗ на фронтенд предписывало браузеру ходить за токеном
  прямо в Supabase. Так нельзя: GoTrue слушает 127.0.0.1:8000, наружу его
  никто не проксирует, а наш собственный CSP `default-src 'self'` запретил
  бы этот запрос и при доступном адресе. Признак, что решение было принято
  раньше и потерялось: в nginx уже лежал `location /api/auth/` с
  ограничением частоты, а в `.env.example` — `SESSION_COOKIE_SECURE`.
  Отсюда правило: перед тем как выполнять инструкцию из документа,
  проверять, исполнима ли она в развёрнутом виде.
- **18–22.09.2026** сервер «принимал TCP и сразу рвал» на 22, 80 и 443, и
  это приняли за поломку на хосте. На деле ВМ была выключена гипервизором
  AdminVPS (`qemu-ga: guest-shutdown`, 18.09 05:02), а соединения принимал
  посредник на пути с рабочей машины — с неё TCP-connect «удаётся» на любой
  порт, хоть на 31337. Отсюда: доступность порта проверяется протоколом
  (баннер SSH, код HTTP), а не фактом соединения; при «рвёт на всех
  портах» сначала смотреть в панели, включена ли ВМ.
- **23.09.2026** первая выкладка остановилась на `./scripts/setup_tls.sh`:
  «Permission denied». Скрипты выкладки лежали в git с режимом 100644 —
  коммиты идут с Windows, где `core.fileMode=false`, и бит исполнения туда
  сам не попадает. `./scripts/deploy.sh` упал бы так же. Отсюда: режим
  скриптов проверяет тест по индексу git, а не по диску.
